# Security Policy

## Reporting a vulnerability

Report suspected security vulnerabilities in Ankah by opening an issue at:

<https://github.com/jamosdev/ankah/issues>

The issue tracker is public. In the initial report, include a concise description
of the affected component and impact, but do not include credentials, personal
data, or detailed exploit steps that could put users at risk. Ask in the issue
for a private channel to share any sensitive reproduction details. Do not use
the issue tracker for general support questions or non-security bugs.

Please include the Ankah version or commit, affected configuration, and a
minimal description of how to reproduce the behavior when it is safe to do so.
Reports are reviewed as time permits; please allow maintainers time to respond
and coordinate before publicly disclosing technical details.

## Supported versions

Report vulnerabilities against the latest code on the `main` branch. Include
the exact version or commit affected so maintainers can assess whether other
releases are affected. You may run `git rev-parse HEAD` to get your current
commit hash, include that in the issue post so that we are better able to
reproduce and verify the problem.

## Out of band communication

No security issue will be tracked until the github issue is created. After
you have done that, you may then send an email to <mailto://jamosdev@protonmail.com>
with additional details if you must, but include the address from the URL bar
of the issue page at the top of the email body. Emails will not be usually
responded to or monitored unless a comment in the github issue reminds to look
at that.
